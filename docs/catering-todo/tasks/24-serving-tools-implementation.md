# 24 — הכלים הנדרשים להגשת המנה

17.11.2026. המשתמש אישר מימוש ניהול עצמי של כלי מנות לפי חד פעמי/אמיתי ואישי/מרכזי, וכן עריכת שולחן אוטומטית לפי תפריט. משימת חבילת המנות של שולחן מתוק נשארת דחויה.

## מומש
- הרחבת DishServingSet הקיים בשדה serving_mode (personal/central), ללא מערכת מלאי נוספת. dishware_type משתמש ב־disposable/real עבור ההגדרות החדשות. כלי מקושר ב־tool_id לקטלוג tools, והסיווג האמיתי שלו קובע אם הוא חוזר. אפשר להגדיר כלי חד פעמי כחלק מאירוע עם כלים אמיתיים לפי המקור.
- לשונית במנות בשם המדויק שביקש המשתמש. אפשר להוסיף, לערוך ולמחוק אפשרות וכלי, לבחור סוג כלים וצורת הגשה, בסיס וכמות, ולשמור ברירת מחדל לכל סוג כלים בנפרד. שמירה פרטנית עם הודעות הצלחה/שגיאה. אין קליטת JSON לצורך ניהול הכלים.
- בחירה אוטומטית בשרת לפי is_real_dishes. שינוי הסוג משמר צורת הגשה של בחירה קיימת כשיש אפשרות מקבילה. אין נפילה שקטה לסוג לא מתאים. בחירה באשף מסוננת לפי סוג הכלים ונטענת מחדש מהשרת. חסר מיפוי גורר אזהרה בסיכום.
- בסיסים חדשים place_setting ו־serving_group: עריכה לפי כל המנות או מחצית במתוק, לפי הסיווג השמור בתפריט בלבד; קבוצות = ceil(עריכה/8). בסיסי החישוב הישנים נשמרו לתאימות, ללא שינוי גורף של חישובי תוספות אחרים.
- MenuTemplate.table_setting_items: שורות עריכה הניתנות לניהול בתפריט, כמות למקום ערוך וקישור נפרד לכל סוג אירוע. ברירות מחדל מ־E8:E9 בגיליון כלים. אין קישור מלאי לפי התאמת שם; מוצגת אזהרה אם טרם קושר פריט. אין המצאת ספייר/מלחיות/ברכונים/מכפיל שבת. תפריטי מגשים מוחרגים מעריכה אוטומטית. עריכה ידנית שנשמרה באירוע בשדה event_tool_set_items נשמרת כחריג ומחליפה את עריכת התפריט, עם הודעה, למניעת כפל.
- איחוד כלי עריכה/מנות שומר contributions; נתיבי PDF מלצר וקייטרינג מקבלים כמות כלי מנה מהמנוע כאשר קיימים פרטי מקור. snapshots מאושרים נשמרים; מסמכים ישנים ללא metadata שומרים fallback קיים. לא בוצע שינוי עיצוב PDF או בדיקת PDF חזותית חדשה.
- קטלוג הכלים נטען בכל העמודים, עד 200 בכל בקשה. שני המסכים משתמשים ב־getAllTools.
- מיגרציות m6b7c8d9e0f1 ו־n7c8d9e0f1a2 הוחלו מקומית באמצעות עזרים מגודרים, לאחר גיבוי SQLite לכל שלב ובדיקת תקינות. לא הוזנו מיפויים עסקיים משוערים ולא נמחקו נתונים.

- 42 בדיקות Angular עברו במסכי מנות, תפריטים ואשף, כולל סינון לפי סוג כלים ושמירת הגדרות עריכה ללא שינוי מוקדם של הנתונים המקוריים. ngc עבר.
- נבדקו בדפדפן המקומי פתיחת מנה, הלשונית, הוספת אפשרות ושורת כלי ללא שמירה; נבדק טופס שולחן מתוק ובו 5 שורות עריכה עם קישורים נפרדים. GET menus החזיר 5 שורות במתוק ו־6 ברגיל. בדיקות API פועלות במסד מבודד לפני app import.
- רשימת הכלים שנצפתה בקטלוג המקומי כוללת 17 פריטים, כולם מסווגים אמיתי. אין להסיק שכלי בשם שקוף הוא חד פעמי; לא שונו הסיווגים ולא נוצרו פריטי חד פעמי ללא מיפוי.
- git diff --check לא היה זמין בגבול המאגר הנוכחי (Not a git repository); אין לטעון שבוצע.

## למשתמש
מנות: http://localhost:4200/dishes → עיפרון → הכלים הנדרשים להגשת המנה → הוסף אפשרות הגשה → סוג כלים וצורת הגשה → הוסף כלי, כמות ובסיס → שמור אפשרות. מומלץ להגדיר ברירת מחדל בכל סוג כלים.

תפריטים: http://localhost:4200/menus → עיפרון → כלי עריכת שולחן — חישוב אוטומטי → קישורי מלאי לשני הסוגים → שמור. בתפריט חדש לשמור תחילה ואז לפתוח עריכה לקבלת שורות ברירת המחדל מהשרת.

בדיקה ידנית מוצעת באירוע טיוטה חדש: רגיל 80 מנות → 80 מקומות, 10 קבוצות; מתוק 80 → 40 מקומות, 5 קבוצות. קישור קערה אחת וכף אחת לכל קבוצה מניב 10/5 מכל אחת. שינוי סוג כלים בוחר אפשרות מתאימה; רענון שומר את בחירת ההגשה. את הכלים האישיים לפי כמות מנה חלקית יש להגדיר ביחס הנכון; חישוב כמויות חבילת שולחן מתוק עדיין דחוי, ואין להציגו כממומש.
